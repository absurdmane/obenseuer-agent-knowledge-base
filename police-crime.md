# Police, crime, witnesses, stolen goods

Scope: how police NPCs behave (`Act_Police`, patrol/route data, speeds), how a crime is recorded and witnessed, trespassing areas, stolen-goods marking and the arrest/search flow. Not covered: dialogue content of questioning, Prison scene details, bribery maths, NPC schedules in general, pathfinding internals.
Status: code-only (partly read; unread parts listed at the end)
Related: [combat-npcs.md](combat-npcs.md), [inventory-storage.md](inventory-storage.md), [player-movement-tiredness-sleep.md](player-movement-tiredness-sleep.md), [levels.md](levels.md)

## Police behaviour: `Act_Police` [code]

NPCs run one `NPC.Activity` at a time; police use `Act_Police` (not BehaviorDesigner: the `.json` behaviour data only picks activities). States: `Idle, Stand, Patrol, Wander, ChasePlayer, QuestionPlayer, SearchingPlayer, SearchingPlayerAgressive`. `StartState` per state:
- `Stand/Idle`: `MoveToPost` -> `NPCController.SetTargetNode(center.node)` (a scene `Node`; if it is in another level, `MoveToOtherLevel`). Speed `SlowWalk`.
- `Patrol`: walks `patrolPoints` (a list of `NodeReference`, i.e. scene `Node` objects, loop through them via `SetTargetNode(node, onArrive: MoveToNextPatrolPoint)`); with no points it falls back to `Wander` or `Stand`. `SetNodeGroup(NodeGroup)` fills the points from a `NodeGroup` (`nodes`, `loop`). Speed `SlowWalk`.
- `Wander` / `SearchingPlayer*`: `GenerateNewDestination`: an A* `ConstantPath` of `range` around `center` (or the NPC), a random graph node as the target (`SetTargetPosition`), repeat on arrival. The state is swapped by `timeUntilStateChange` (in game seconds, `stateTime` 1000..7200) via `SuffleNewState`, using `standEnabled/patrolEnabled/wanderEnabled`.
- Speed: `NPCController.movementAnimation.SetMovementSpeed(OpenSewerNPCMovementAnimation.MovementTypes.SlowWalk | FastWalk | Run)` (enum in `OpenSewerNPCMovementAnimation`, a `RichAI` wrapper). Chase sets `Run`, question sets `FastWalk`; `originalSpeed` is stored but the code that restores it was not read. To make a cop run, set `Run` on `movementAnimation`.
- `Act_Patrol` (separate `Activity`, `PatrolMode`, `NodeGroup`, `GoToRandomNode`, `GoToNode(index)`) is the generic civilian patrol; police do not use it.
- Where routes live: scene `Node` / `NodeGroup` / `NodeReference` objects (`NPC/Node.cs`, `NodeGroup.cs`) and `NodeNetwork`; `NPCData` carries `startScene`. Names of the scene objects are asset data (not in code). Enumerate at runtime with `Object.FindObjectsOfType<Node>()` / `NodeGroup`.
- `Crime.activePolices` holds the running `Act_Police`; `Crime.CallPolice(caller, severe, ignoredistance)` makes those within 15 m (or all) `StartChase()` (severe) or `StartChaseQuestion()`.

## Detection and the stolen-goods "sense" [code]

`NPC_FOV` (cone `FOV` 90, `maxDistance` 30, probability by focus/edge, cooldown 0.5 s, ray check) raises `PlayerDetected`. `Act_Police.OnPlayerDetected(npc, ref)`:
- ignored while `talking` or `Crime.ArrestInProgress`;
- in `SearchingPlayer` -> `QuestionPlayer`; in `SearchingPlayerAgressive` -> `ChasePlayer`; while chasing/questioning it just resets `lostVisibilityTimeRemaining = 10`;
- otherwise (unless `onlyDetectNewCrimes`): `num = Crime.CountCrimes(countStolenGoods: true, valueThreshold: 100, itemCountThreshold: 10, victim)`. If `num > prev + 100` the check re-arms. If `num > Random(0, 750)` (350 for the "Police" start) and not already checked -> `OnPlayerCommitingCrimeDetected`: `Crime.CheckCrimesForArrest(0.25 or 1.5)` -> `StartChase()`, else `StartChaseQuestion()`; plus a bark.
- **This is the place to replace**: the "sense" is `CountCrimes` with stolen goods (value of stolen stacks x 0.1, only if more than 10 stolen stacks and > 100 value). It never looks inside inventory per item at the stop. A mod can patch `Act_Police.OnPlayerDetected` or `Crime.CountCrimes`, or run its own search on `QuestionPlayer` start.

## Chase, question, arrest [code]

- `ChasePlayer` (`ChasingPlayer`): `Run`; every time the player moved > 1 m it calls `SetChaseDestination(playerPos, 0.1)`; after 10 s without detection -> `SearchingPlayerAgressive`; at distance < 1.25 m, after a 1 s grace, not in dialogue/level change -> `Crime.GoToPrison()`.
- `QuestionPlayer`: `FastWalk`, closes to < 1.75 m, `InteractableTalk.ForseStartDialogue()` (the police conversation, `PoliceIdle` Lua variable), then returns to `Idle` and reshuffles states after the talk. Dialogue scripts decide fine/bribe/arrest: `Crime.CanPayFine/PayFine`, `TryToBribe/CalculateBribe`, `GoToPrison`, `RelayGoToPrison`; `Crime.ConfiscateItems(storage, ...)` (called from the prison flow/dialogue) moves all non-owned player items into a storage and deletes stacks with `ownerId > 0`.
- `Crime.GoToPrison(severityFactor)`: stops all pursuits (`StopPolicePursuits`, `OnPlayerArrested`), adds a Theft record of 10% of `CountStolenGoodsValue()`, multiplies records, forces a pass-out (`WaitingController.PassOut(Arrest)`) with a 10 s `SleepEvent(Arrest)`; `SleepEventController.Event_Arrest` plays arrest sounds, **`RemoveStolenGoods` deletes every stack from `Inventory.GetStolenItems()`**, then `Crime.TeleportToPrison()` (`SaveController.ChangeLevel(prisonLevelName, prisonEntrypoint)`, time speed reset to 1).
- Arrest while sleeping: `WaitingController.StartSleep` rolls `Crime.CheckCrimesForArrest(crimeArrest)` and if true and `canBeArrested` queues `SleepEvent(Arrest)`; `Event_GetCaught` (random sleep event) also removes stolen goods and arrests if `CheckCrimesForArrest()`. So sleeping with stolen goods is a second, independent arrest path (no cop NPC involved).
- `CheckCrimesForArrest(chance)`: `CountCrimes()`; only if > 100; arrest when `count / 1000 * chance > Random(0,1)`.

## Crime and witnesses [code]

- `Crime.CommitCrime(victim, severity, type, silent)` adds to a `CrimeRecord` per (victim, type) (generic record if no victim), shows a notification. Types: Unspecified, Theft, Violence, Fraud, PrisonEscape, Administrative, AnimalCruelty, Trespassing, Burglary, None, Harassment, Vandalism, Terrorism.
- `Witness` (component on NPCs and `SurveilanceCamera`s): `Witness.IsWitnessed(invoke, type)` loops all registered witnesses; one counts if its `NPC_FOV.CheckIfPlayerIsDetected()` and `Random <= propability` (0.5 default); `onWitnessed` fires after 0..2 s. Several crime sources call `IsWitnessed()` before `CommitCrime` (e.g. theft in `Inventory.CheckForAddedStolenItems`, melee hits on NPCs, `SpawnItemOnBreak`), not all were checked. `Witness.GetWitnesses(excluded, maxDistance)` lists the ones that see the player now. **Witness -> police reaction (corrected):** `Act_Police.SetStartNPCSettings` sets the cop's own `Witness.onWitnessed = Act_Police.OnPlayerCommitingCrimeDetected` and `Witness.propability = 0.9`. So when a crime source calls `Witness.IsWitnessed(invoke: true, WitnessType.Crime)` (the default) and a cop's `NPC_FOV` sees the player and wins the 0.9 roll, `WitnessedDelay` waits 0..2 s and then calls `OnPlayerCommitingCrimeDetected` -> `Crime.CheckCrimesForArrest(0.25, or 1.5 with the Police start)` -> `StartChase()` (Run, then `GoToPrison` within 1.25 m) else `StartChaseQuestion()` (FastWalk, dialogue). The arrest roll needs total crimes (incl. stolen goods) over 100 and `count/1000 * chance > Random`, so a seen small theft often ends in questioning, a big one in a chase. The theft record is added right after `IsWitnessed()` returns, before the delayed callback, so the callback already counts it. Other paths: `Act_Police.OnPlayerDetected` (periodic crime count, above) and `Crime.CallPolice(caller, severe, ignoredistance)` (cops within 15 m: `StartChase()` if severe, else `StartChaseQuestion()`; no witness needed).
- Trespassing: `TrespassingArea` (scene trigger volume; `victim` NPC, `severity` 100, `crimeType` default Trespassing, `npcs` list whose `NPC_FOV.PlayerDetected` is subscribed, `genericDetection`, `areaDisabled`). While the player stays inside (`OnTriggerStay`, tag "Player") `trespassing` is true; the crime is committed once (`detected`) when one of the listed NPCs detects the player, or at once when `genericDetection` and `Witness.IsWitnessed()`. After exit a 1 s cooldown resets. It is purely scene-placed; there is no ownership logic ("this apartment is not yours") in code; locked doors are `Door.Locked` plus scene relays.

## Stolen goods [code]

- A stack is "stolen" when `ItemStack.ownerId > 1` (owner NPC id) in any `Inventory.AllSlots()` slot (`Inventory.GetStolenItems()`, `ownerId` filter optional); the `ItemOwnerPermission` meta with `ownerPermission == true` exempts a stack. `ItemStolenData.playerStolen` meta is set by `Inventory.CheckForAddedStolenItems` (item entered the player's slots with an owner >= 2; then, if witnessed or `reqruireWitness == false`, a Theft crime of 10% of the sale price x amount against the owner). It is per stack (meta on the stack), so a per-item roll means iterating the stacks and rolling per stack or per unit of `itemAmount`.
- Confiscate only found items: delete or move individual `ItemStack`s from `GetStolenItems()` (`stack.RemoveStack()` as `SleepEventController.RemoveStolenGoods` does, or `ItemOperations.MoveStackToStorage`); the `Crime.CountStolenGoodsValue()` used by `GoToPrison` would then count what is left. The backpack: `GetStolenItems` uses `AllSlots()`, which includes character slots/backpack as the game defines them (see [inventory-storage.md](inventory-storage.md) for what `AllSlots` covers with the Backpack mod).

### Where stolen goods are removed after each outcome [code]

- Fine: `Crime.PayFine()` first `RemoveStack()`s every stack from `Inventory.GetStolenItems()` (even when the player then cannot pay), then `Money.Buy(GetCrimeFineAmount(), RealMoney)` and `ClearCrime()`. `GetCrimeFineAmount` = `CountCrimes(countStolenGoods: false) * crimeFineMultiplier`; `GetSentenceLengthInHours` also ignores stolen goods; only the arrest-decision paths (`CountCrimes` with `countStolenGoods` true, `GetCrimeAmount`) count them. `CanPayFine` is a Lua-registered check; `Crime` registers `HasStolenGoods`, `CountStolenGoodsValue` and others as dialogue Lua functions.
- Arrest by cop: `GoToPrison` -> sleep event `Arrest` -> `SleepEventController.RemoveStolenGoods` (all stolen stacks deleted) -> prison; inside the prison flow `Prison.ConfiscateItems` calls `Crime.ConfiscateItems(activeCell.confiscatedStorage, clearStorage, backpackSpot)` which moves non-owned items to the cell storage and deletes owned (`ownerId > 0`) stacks.
- Returning goods by dialogue: `DialogueEventSystem.GiveStolenItemsAndReturnHalfOfOC(owner)` removes the stolen stacks of one owner and pays their value in OC. `LegalServicesController` / `logic_crime` clear records (`ClearCrime`).
- So there is no per-item search anywhere in vanilla; every outcome deletes or moves all stolen stacks. A mod needs its own loop over `Inventory.GetStolenItems()` (stack-level `ownerId`, `ItemStolenData` meta).

## Prison [code]

- `Prison` (scene `SavableScript`, saved: `clearStorage`, `inPrison`, `activeCellIndex`, `onPassTimeCooldownRemaining`) has `prisonCells[]`, each `Cell`: `playerSpawnpoint`, `prisonBed` (`Sleep`), `confiscatedStorage` (a normal `Storage` in the prison scene), `backpackSpot`, and relay arrays `OnImprisoned/OnRelease/OnPassTime/OnEscape` (also on the prison itself). Entrypoint `prison` (`Prison.entrypoint._OnPlayerSpawn = ImprisonPlayer`); `Crime.TeleportToPrison` = `SaveController.ChangeLevel(info_game_logic.prisonLevelName, prisonEntrypoint)`.
- `ImprisonPlayer` (runs on spawn at the entrypoint): time speed 1, random cell, `Teleport.TeleportPlayerToTargetStatic(cell.playerSpawnpoint)` (reusable to put the player back in a cell), `ConfiscateItems(clearStorage)`, fires the relays, sets the wake-up callback `PassTime`, subscribes `DeltaSeconds`. `DeltaSeconds` burns the crime records down at `crimePerPrisonHour`; release when all are 0 after at least 300 s, or after `(100 + timesInJail * 12)` hours: `Release()` = `ClearCrime()`, fires relays. `Escape()` fires `OnEscape` with the sentence time (the escape crime itself is added by scene relays / `TrespassingArea.ChangeCrimeTypeToPrisonEscape`, not here).
- `Prison.ConfiscateItems(clearStorage)`: for every other cell (or all if `clearStorage`) with items and an `overflowPackagePoint`/`overflowPackagePrefab`: puts that cell's items into a `CollectiblePackage` at `overflowPackagePoint` (instantiated once, items appended), empties the cell storage, sets the guard actor field `HasBagItems`; then `Crime.ConfiscateItems(activeCell.confiscatedStorage, clearStorage, backpackSpot)`: `Storage.Empty()` if `clearStorage`, the worn backpack (character slot 5) is spawned at `backpackSpot` when not owned, every other player stack with `ownerId < 1` is moved into that storage (`MoveStackToStorage(..., deleteFailed: true)`, so what does not fit is deleted), owned stacks are deleted. `Prison.ClearStorage()` only sets the flag for the next imprisonment; `ChangeCell(i)` moves one cell's storage into another.
- So the confiscated goods sit in the active cell's `confiscatedStorage` for the whole sentence and are NOT returned automatically on release by code in `Prison`; they stay there (and move to the overflow package next time) unless scene relays/dialogue (`HasBagItems`) give them back. Whether that storage is locked, and its `Lock.Difficulty`, is scene data (each `Storage` has a `Lock _Lock`): not in code.
- Guards: scene NPCs (dialogue actor `Generic_Prison_guard`); their activities and any sleep state are scene/`NPCBehavior.json` data and were not read. `Act_Sleep` exists as an activity.

## Lockpicking [code]

- Trigger: `Lock.Use(callback, parent)` (every `Storage` and `Door` owns a `Lock`): not locked -> open; player has the `keyItem` task item -> unlock; else if `Lockpickable` and the player wields an item of category "Lockpick" (`PlayerLockpicking.CheckIfPlayerHasLockpick`) -> `onLockpickingStart` relay and `PlayerLockpicking.ToggleLockpicking(LockpickSuccessCallback, Difficulty, lock)`; otherwise `onLockedUse` and false.
- Lock fields (per object, serialized, not `fsIgnore` except noted): `Locked`, `Lockpickable`, `Difficulty` (0..2, default 2; tooltip: effortless 0.1, easy 0.2, moderate 0.3, challenging 0.8, difficult 1.9), `LockAfterTime` (relock after game seconds), `increaseLockDifficulty` + `difficultIncreaseAmount` 0.33 (the lock gets harder each time it relocks, capped at 2), `keyItem`, `UnlockDelay`. Settable at runtime: `lock.Difficulty = x; lock.Locked = true; lock.Lockpickable = true;`.
- Chance: `PlayerLockpicking.LockpickChance(difficulty)` = `(1 - 1/(0.1 * skill + 1)) * (1 - alcohol/100) * (1 - mushroomsHigh/100) / difficulty`; the label thresholds: > 0.75 Effortless, > 0.33 Easy, > 0.125 Moderate, > 0.05 Challenging, > 0.015 Difficult, else Impossible. Skill is `PlayerStats.GetSkill(PlayerSkillType.Lockpicking)`; success raises it by `1/(chance^2 + 35 chance)` (clamped 0.01..1), failure by 20% of that.
- Resolution: `PlayerLockpicking.LockpickingProcess` runs `LockpickUI.StartLockpick(difficulty, chance)` (a minigame; `WasSuccess()`), `CallbackSuccess(true/false)`. Failure/cancel hooks: `LockpickUI` breaks the pick via `PlayerLockpicking.BreakLockpick()` (removes the wielded lockpick, `Lock.LockpickBroke` -> `onLockpickingFail`); `Lock.AbortLockpicking` (also `onLockpickingFail` + `onLockpickingEnd`); `Lock.LockpickSuccessCallback(false)` -> `onLockpickingFail`. Hookable methods: `PlayerLockpicking.BreakLockpick`, `Lock.LockpickSuccessCallback`, `Lock.AbortLockpicking`, `PlayerLockpicking.LockpickingProcess` (coroutine).
- Witnesses: **while the minigame runs**, each 0.01 s `Witness.IsWitnessed()` is checked; the first time it is true (success or not, independent of the result) `Crime.CommitCrime(null, (int)(200 * difficulty), Burglary)` is added once per attempt. The player must keep looking at the lock (0.33 s grace) or it stops.

## Pathfinding and doors [code]

- Two systems: A* (`AstarPath`, `RichAI` via `NPCController.ai`) inside a scene, and `NPCPathfinding` (waypoint graph, `Waypoint`, `Waypoint_Door`, `Waypoint_LevelChange`, `InterScenePathfindingGraph`) for routes across doors and scenes. `NPCController.SetTargetNode/SetTargetPosition` ask `NPCPathfinding.SearchForPath`; `SetFollowDestination` sets the A* destination directly; `SetChaseDestination` picks follow when a path exists on the graph, otherwise `SetTargetPosition`.
- Locked doors: `Waypoint_Door.TravelsableByNPC`: a door is passable if unlocked, or the NPC is in `NPCsWithKeys`, or `policeCanOpen` (default true) and the NPC's current activity is `Act_Police`. So a cop on any police state passes locked doors that have a `Waypoint_Door`; apartment interiors are on the same scene graph as the building in the tenement scene (not verified: needs the scene).
- Points per building/room to use as patrol targets: scene `Node`s (and `NodeGroup`s), `NodeReference`; furniture areas are described in [furniture-areas.md](furniture-areas.md). Not read: how apartment doors/rooms are exposed to `Node`.

## Apartments, patrol targets, fleeing [code]

- Apartment data: `TenementController.instance.apartments` (`List<TenementApartment>`; `GetApartmentFromNumber(n)`, `GetApartmentByResidentId(id)`). `TenementApartment`: `apartmentNumber`, `apartmentFloor`, `type` (`TenementApartmentType`), `prefabs`/`tenementApartmentPrefabs` (`TenementApartmentPrefabs`, the live scene object: `.apartmentNumber`, `.furnitureManager`), `resident` (`TenementResident`: `resident` `NPCReference`, `otherResidents`), `locked` (bool, a data flag; its users were not found in the files read, so do not rely on it for the door), `onlyFurniture`, `moveStarted`, `evictionStarted`. The player is the landlord: rented apartments have `resident != null`; the player's own apartment is the "Player" one (`TenementResident.CantRentReason.PlayerApartment` names it; scene object `Apartments/Apartment 1 - Player`, see [furniture-areas.md](furniture-areas.md)).
- Is the player inside apartment X: `BuildingArea.currentManager` (static `FurnitureManager`, set on area `Enter()`) -> `.tenementApartmentPrefabs.apartmentNumber` (null for stairs/outside areas: then `area` is Stairs/Communal/...; `FurnitureManager.area == Furniture.BuildingArea.PlayerApartment` is the player's own). Cheapest check each tick. Not owned by the player = `TenementController.instance.GetApartmentFromNumber(n).resident != null` (a resident lives there) and it is not the player's apartment.
- Entrance door: `Door` has `public Lock _Lock` (`Locked`, `Difficulty`) and `Door.Locked`; `ApartmentDoor` is an empty marker `MonoBehaviour` (no code uses it, so the link apartment -> door is scene data: put on the door object, or find the door nearest the apartment). Key ownership is `Lock.keyItem` (`TaskItem`) + `TaskItemsManager.CheckIfPlayerHasTaskItem`; `Lock.PlayerHasKey()`.
- Patrol targets inside apartments: `TenementApartmentPrefabInfo.residentNodes` (`ResidentNodes`: `List<Node> nodes`, `chairs`, `beds`) are the resident spawn/idle spots in each apartment prefab (`Node.npcsAtNodeList`). Whether stairwell/hall `Node`s/`NodeGroup`s exist is scene data; offline names not read. A runtime dump should list: all `Node` (name, scene path, position, `npcsAtNodeList.Count`), all `NodeGroup` (name, `nodes`, `loop`), all `Waypoint`/`Waypoint_Door` (door name, `_Lock.Locked`, `policeCanOpen`), all `ApartmentDoor` (path, has `Door`), all `Act_Police` instances (`state`, `patrolPoints.Count`, `center`, `range`), each `TenementApartmentPrefabs` (`apartmentNumber`, `residentNodes.nodes.Count`).
- Fleeing: the player's run flag is the private `walking` field of `OpenSewerCharacterController` (`walking == false` and not crouching -> run speed; see [player-movement-tiredness-sleep.md](player-movement-tiredness-sleep.md)); read it by reflection, or compare `GetTargetSpeed()` / horizontal velocity with `_runSpeed`.
- Cop state from outside: `Act_Police.state` is a public field (`Act_Police.State`); `IsPursuingPlayer`, `QuestioningPlayer()`, `ArrestingPlayer()` are public. Get the instance via `Crime.instance.activePolices` (private list behind `AddToActivePolices`; the class `Crime` exposes `IsNPCPolicing`) or `NPCData.state.CurrentActivity as Act_Police` (`NPCDirector.globalDatabase`).
- Speed restore: `originalSpeed` is stored in `SetStateChasePlayer`/`SetStateQuestionPlayer` but **never read**. The speed returns to normal only because `StartState` for Wander/SearchingPlayer*/Patrol/Idle/Stand sets `SlowWalk` again after a chase (lost sight -> `SearchingPlayerAgressive` -> `StartNewState` -> `StartState`).

## Police conversation, fine and bribe [code + data]

- Where: dialogue database (PixelCrushers `DialogueDatabase`, one asset; dump with `dialogue_export.py`) conversation `Police/Police` (id 88, actor `Generic_Police`) is the questioning/turn-in menu; `Generic/CrimePolice` (id 117) are only chase barks. The cop's `Act_Police.PrepareDialogue/RegisterDialogue` sets the Lua variable `PoliceIdle` (false while pursuing, true when idle). Menu: entry 1 (if `PoliceIdle == false`) offers: pay fine (`CanPayFine()`, `PayFine()`, shows `GetCrimeFineAmount()` in RM), bribe (text `"(Bribe - [lua(CalculateBribe())] OC)"`, condition `CheckMoneyDialogue(CalculateBribe(), false)`), run (`StartChase()`), "I'm innocent" (if `GetCrimeAmount() > 0` -> `GoToPrison(1)`); the bribe entry goes to `TryToBribe() == true` -> "That'll do" (end) else -> `GoToPrison(1.25)` (sentence x1.25). Idle cop: "turn myself in" -> pay fine / bribe / `GoToPrison(0.7)` (shows `GetSentenceLengthPreArrest(0.7)`). Other entries are quest-specific and not covered.
- Lua functions registered by `Crime.Start` (`Lua.RegisterFunction(name, crime, MethodInfo)`): `GetSentenceLengthPreArrest`, `GetSentenceLength`, `GetCrimeAmount`, `GetCrimeFineAmount`, `CountStolenGoodsValue`, `GoToPrison`, `TeleportToPrison`, `PayFine`, `CanPayFine`, `CanBribe`, `TryToBribe`, `CalculateBribe`, `HasStolenGoods`.
- Formulas: `CalculateBribe` = cached `latestBribe = round(CountCrimes() * 5 / q)` where `q = max(0.25, PlayerStats.SkillQuality(Bribery, 0.35))` (so x5 .. x20 the crime count, stolen goods included); once computed it is kept until paid. If the player has less OC than that the *returned* number is all his OC (at least 100) but `latestBribe` stays high, so the bribe then fails the money check. The amount is fixed by the formula, the player cannot choose it. `TryToBribe`: sets `triedBribe = true`; roll `PlayerStats.SkillSuccess(Bribery, Recipe.CurrentFailChance(0.7, Bribery))`; if `latestBribe == 0` (CalculateBribe was never called) it clears all crimes free and succeeds; else if the roll succeeded and `Money.CheckMoney(latestBribe)` -> `Money.Buy(latestBribe)` (OC), `latestBribe = 0`, `ClearCrime()` (all records set to 0; stolen goods stay in the inventory) and returns true; otherwise false, no money taken. A refused bribe has no code consequence inside `Crime`: the conversation sends the player to `GoToPrison(1.25)`. `CanBribe()` is `!triedBribe`, reset only by `ClearCrime(victim[, type])` (not by the argument-less `ClearCrime()` that `TryToBribe` calls).
- Fine: `CanPayFine` = fine > 0 and the player has that much RM; `PayFine` removes all stolen stacks, then charges the fine (RM) and `ClearCrime()` (see above). Fine = `round(CountCrimes(countStolenGoods:false) * crimeFineMultiplier)` (1.5).
- Changing it from a mod: (a) Harmony patch `Crime.TryToBribe/CalculateBribe/CanPayFine/PayFine` (the Lua registrations hold the `MethodInfo`, so a patched body is what the dialogue runs); (b) register a Lua function of the same name after `Crime.Start` (`Lua.RegisterFunction` replaces the global; not verified in game); (c) edit the loaded database at runtime: `PixelCrushers.DialogueSystem.DialogueManager.MasterDatabase.GetConversation(88)` -> `dialogueEntries` (change `DialogueText`/`MenuText`, `conditionsString`, `userScript`, add an entry and an `outgoingLinks` link from entry 1); not verified in game, and the database should be patched again after a scene/database reload. A new option can call your own registered Lua function.

## NPC footsteps [code]

- One shared component for the player and all NPCs: `UnityStandardAssets.Characters.ThirdPerson.FootSteps` (serialized `player` bool, `byDistance`, `additionalVolume`, `audioSource`, `audioSource2/3`, `audioSourceSecondary`, `oSMaterialList`). Not police-specific; no occlusion/low-pass code (plain 3D `AudioSource`s, so walls and floors do not damp it).
- Flow: `Update` (when `byDistance`) counts horizontal distance, a step every 1.5 m while grounded and moving (otherwise animation event `Step()`); `PlayStep` -> ground collider -> `OSMaterial` (via `ObjectOSMaterial`, `FootStepsSurface`, or the mesh sub-material name) -> `PlayFootstep` -> `OSMaterialList.PlaySoundAndEffect(material, FootStep, pos, normal, additionalVolume, audioSource: player ? null : audioSource)` -> `RandomAudio.PlayRandomClip`. For NPCs the NPC's own `audioSource` is used (`SetRandomClip(..., setVolume: true)` then `Play()`), so volume, `minDistance`, `maxDistance`, `rolloffMode`, `spatialBlend` come from that `AudioSource` on the NPC prefab (asset data, not in code; values unknown, need a runtime dump). The player passes `null`, which spawns a temporary effect object instead.
- To quiet police only: for an `Act_Police` NPC take `npcController.GetComponentInChildren<FootSteps>()` (fields are public for the sources) and set `audioSource`, `audioSource2`, `audioSource3`, `audioSourceSecondary` `.maxDistance` / `.minDistance` / `.rolloffMode` (do it once when the NPC is set up; `setVolume` may rewrite `.volume` per step, so prefer distance/rolloff or a postfix on `RandomAudio.SetRandomClip` that scales `source.volume` for sources owned by police). Which `AudioMixerGroup` they use is also prefab data (`RandomAudio.audioMixer` overrides it).
