# Power grid (added in build 0.5.13)
Scope: the `PowerGrid` network that supplies electric devices, its listeners, the tenement's main grid and resident load, billing and the meter, saving, and how this replaced the old `FurnitureStats` budget. Which scene and prefab objects carry grids is asset data and is not covered. Device-level power (`PowerSource`, fuel, fridges, lights) is in power.md.
Status: code-only (new in 0.5.13; nothing played)
Related: [power.md](power.md), [fuel-heat.md](fuel-heat.md), [tenement-upgrades.md](tenement-upgrades.md), [tenement-rent.md](tenement-rent.md), [doors-interaction.md](doors-interaction.md)

## Where it lives [code]

- `PowerGrid` (SavableScript, `IPowerGridListener`): members `GridEnabled`, `BaseCapacity`, `unlimitedCapacity`, `unstableSupply`, `countCumulative`, `cumulativeBalance`, `global`, `ParentGrid`. `PowerGridsController` (singleton, global save). `PowerGridListener` (a switch with a fixed draw, `On` saved, `PowerConsumption` default 100, outputs `OnPowerOn/OnPowerOff`). `IPowerGridListener` (`IsOn`, `PowerBalance`, `OnGridPowerOn`, `OnGridPowerOff`, `OnPowerGridUpdated`). `PowerSource` joins grids too (`JoinGrid`, `SyncWithGrid`, `UsesGrid`, `PowerBalance` (`-powerConsumption`, or `-powerConsumptionOverride` while `overridePowerConsumption` is set, 0.5.17), `powerConsumption` default 60). `TenementResidentPower`, `TenementUtilities`, `PowerMeter`, `ElectricitySubscription`, `PowerLightFlicker`, `Logic_Subscription`, `RelayDayNight` are the other new types.

## How it works [code]

- Every listener has a `PowerBalance` in watts (negative consumes, positive produces). Grid numbers: `localBalance` (sum over supplied, switched-on listeners), `NetCapacity` = base + local + children's export, `FreeCapacity` (uses the parent when connected), `Unlimited`, `Flickering`, `GeneratorFuelLeft`. Grids form a tree (`SetParentGrid`, `GetRoot`, at most 16 hops); a child can draw on its parent's free capacity.
- `PowerGrid.UpdateGridStatus` (every subscribe, unsubscribe, toggle, base-balance change and child change) notifies every listener (`OnPowerGridUpdated`). If free capacity is negative or the grid is off it cuts consumers with a negative balance, most recent switch-on first (`OnGridPowerOff`); otherwise it restores cut consumers in switch-on order while capacity allows (`OnGridPowerOn`). Re-entrant calls are queued (at most 8 passes). `GridEnabled = false` makes `IsPowered` false for all listeners.
- Membership: `PowerSource.JoinGrid/SyncWithGrid` and `PowerGridListener.Start` find a grid with `GetComponentInParent<PowerGrid>()`, else through the placed furniture's area manager (`FurniturePlaceable.manager.powerGrid`, `FurnitureManager.powerGrid`); placed or taken furniture reconnects with `BuildingSystem.ReconnectPower/DisconnectPower`. A `PowerSource` joins only if `UsesGrid`: a non-`AlwaysOn`, non-fuel electric device, or a generator marked `isGenerator`.
- A device learns about power through the grid: `PowerSource` implements `IPowerGridListener`, and `OnGridPowerOff/On` call `ToggleInput(false/true)`, which fires `CraftingBase.OnPowerOut/OnPowerOn`. The game now writes the saved flag `PowerInput` itself (`JoinGrid` and `SyncWithGrid` set it from `powerGrid.IsPowered(this)`, silently when the device is off). `PowerSource.TogglePower(true)` returns false when the grid lacks free capacity (unless unlimited), so the device cannot start. `PowerGridListener.OnDestroy` and `PowerSource.OnDestroy` unsubscribe; `CraftingBase.OnDestroy` calls `_Power.OnDestroy()`.
- Generator: `Generator.powergeneration` (500, not saved) with `linkToGrid`/`showGridStatus`; with `linkToGrid`, `Generator.Start` sets `_Power.isGenerator = true` and `powerConsumption = -powergeneration`, so it produces on its grid (the old `nominalOutput` is gone). `GeneratorPanel.UpdateGridInfo` shows output and free capacity when `showGridStatus` is set.
- Tenement: `TenementController.CheckElectricity` sets the main grid `powerMain` (`SetBaseBalance`, `unlimitedCapacity`, `unstableSupply`) from the building electricity level and the `TenementElectricity` subscription: None 0 W; Shit 8000 (15000 with the subscription); Good 8000 (100000 with); Best 8000 (1000000 with, and `unlimitedCapacity` when subscribed). Good and Best without the subscription send one mail (`flyerSend`, saved). Each resident apartment is a `TenementResidentPower` on that grid (since 0.5.17 `TenementController.SetApartmentPowerGrid`, called by `TenementUtilities` when `useTenementPower` is set, moves it onto the apartment's own grid; otherwise it stays on `powerMain`): nominal 600 W split 50% wall, 10% bathroom, 40% kitchen, scaled by upgrade level (Bare 0, Makeshift 0.05, Shabby 0.33, Decent 1, Fine 1.5, Luxurious 2; no kitchen 0); its draw is 0 when the apartment electricity is Off, while moving, when only furniture, or without a resident. `TenementController.UpdateUtilities`/`UpdateResidentPower` run on load (`SaveController.LoadingDone`), after an upgrade finishes and after move-in and eviction. `TenementUtilities` (requires a `PowerGrid`; `apartmentNumber` -1 = always powered) attaches its grid to `powerMain` or detaches it when the apartment has no electricity; `TenementApartment` calls `UpdateApartmentPower` when an electricity upgrade finishes.
- Billing and meter: `ElectricitySubscription` (`PlayerSubscription`, `gridName`): `GetCost` = `PowerGridsController.SavedGrid.GetElectricityCost` (0.5.17: -`SavedCumulative`/1000 x `DifficultyInfo.GetElectricityPrice(1f)`, rounded to whole OC, 0 when not positive; in 0.5.13 it effectively returned 0); `Unsubscribe` sends an invoice and a mail; `PaymentHandled` resets the saved balances. `PowerMeter` (Interactable) shows `cumulativeBalance` and turns its disc by `NetBalance`; with `useTenementMain` it reads `powerMain`; `TogglePowerGrid(bool)` toggles the grid; `Interact` only plays a warning. `Logic_Subscription` fires `OnSubscriptionActive/InActive` by subscription id.
- Flicker: `PowerLightFlicker` (created by a `PowerGridListener` that has `LightTurnOffOn` children) flickers those lights while the listener is on and powered and the grid is `Flickering` (unstable supply, or a powered producer), and dims them with low fuel (`lowFuelSeconds` 3600). It sets `Light.intensity` and calls `LightTurnOffOn.SetEmissionMultiplier`, not `on`.
- Fridges: `Storage.showPowerButton` + `powerGridListener` give a per-fridge switch (`Storage.SetPowerSwitch(bool)`, `PowerSwitchedOn`, relays `onPowerOn/onPowerOff` through `RefreshPowerState`); the panel shows the button (`StoragePanelUI`). Broken devices: `CraftingBase.Break()` fires `onBreak`, powers off, sets `broken` and `On = false`; `PoweredAndActive` is false while broken and `Toggle(true)` is refused (`ManufacturingPowerUI.SetBroken` shows "Broken").
- Saving: `PowerGridsController` keeps a saved record per grid GUID (`SavedNetBalance`, `SavedCumulative`) and on load adds the offline net balance times the elapsed hours; `PowerGrid` saves `GridEnabled`, `BaseCapacity`, `unlimitedCapacity`; since 0.5.17 `cumulativeBalance` is no longer saved by the grid (`PowerGridsController` is the only store), the offline usage is applied once per grid per load, and a one-time migration for saves made before 0.5.17 (`billingVersion < 1`) zeroes `SavedCumulative`, so unbilled usage in old saves is discarded.
- Removed: `FurnitureStats` is an empty `[Obsolete]` class, `FurnitureManager.NetPower`/`StatsObjects`/`TurnDeviceOn/Off` are gone, `FurniturePower` is gone.

## Mod guidance

To make electric devices depend on a room or building, use the grid instead of a custom postfix: give the room's objects a parent `PowerGrid` or set `FurnitureManager.powerGrid`, or toggle `GridEnabled`. A postfix on `PowerSource.Powered` still composes with it, but the game overwrites `PowerInput`. Cuts follow switch-on order, so a device switched on last is cut first.

## Changes in 0.5.17 `[code]`

- Difficulty: new settings `DifficultyInfo.electricityPrice` and `electricityAmount` (UI in `DifficultyUI`, texts in `DifficultySettingDescriptions`; changing either calls `TenementController.UpdateUtilities`, so the grid updates live). `electricityPrice` scales only `SavedGrid.GetElectricityCost` (the subscription bill and the per-apartment utility payment). `electricityAmount` scales only the tenement main-grid base capacity in `CheckElectricity` (the 8000/15000/100000/1000000 W values, via `DifficultyController.GetElectricityAmount`); `Infinite` leaves the value unchanged and also makes `unlimitedCapacity` true when the building electricity is not None (`DifficultyController.InfiniteElectricity`); Disabled is not allowed in the UI. Per-device draw and the 600 W resident draw are not scaled.
- Cut and restore (`PowerGrid.RecalculateGrid`): the cut branch needs `(!Unlimited || gridtoggled)` and `(FreeCapacity < 0 || !GridEnabled)`; the restore branch is now `else if (GridEnabled)` and also applies to unlimited grids (`Unlimited || FreeCapacity >= -PowerBalance`). New `PowerGrid.localDemand`, `LocalDemand`, `GridPowerBalance`, `GridDemand` (the last two return the root grid's values); `SetBaseBalance` also updates the saved record (`PowerGridsController.GetByGrid(this)?.UpdateValues()`, no null check on `instance`).
- `PowerSource`: `overridePowerConsumption` (saved flag) with `powerConsumptionOverride` replaces `powerConsumption` in `PowerBalance`; the only writer is `manufacturing` with the new `CraftingBase.PowerConsumptionIdle` (default -1 = off): an idle draw while no craft runs, cleared when a craft starts or ends; `Craft` is refused with a flashing power icon when the grid lacks free capacity for the difference. `PowerSource.TogglePower` checks `FreeCapacity >= -PowerBalance`, but its `powerConsumption <= 0` bypass still reads the raw field.
- `PowerGridListener`: new output array `OnGridUpdated` (fires after every grid update; `Storage` adds entries at runtime for the fridge switch) and the flag `IgnoreFireOnGridUpdates` (suppresses `OnPowerOn/OnPowerOff` from grid updates and from `OnGridPowerOn/Off`; the start coroutine then fires On or Off from the switch state); new `PowerGrid` property.
- `PowerGridsController.SavedGrid`: `GUID` renamed `savedguid` (the old key is not read), new `gridName`, `CumulativeRestored`, `RestoreCumulative`, `GetElectricityCost`; `FindSavedGrid` matches by GUID, then an unlinked entry with the same name; `GetByName` checks `gridName` first (its inverted null test, which made the 0.5.13 lookup return null for any non-empty name, is fixed); scene grids are kept in `sceneGrids` and relinked on load.
- Utilities: the rent-paid block of `TenementController` also calls `PayUtilities`, which pays each apartment's `TenementApartment.GetUtilityPaymentAndResetCounters` (saved grid named "A" + apartment number, its cost, then its cumulative is zeroed) and posts "Utilities paid". `TenementController.apartmentPowerGrids` (not saved) is refilled when `TenementUtilities` runs; `GetResidentPowerGrid`, `GetResidentPower(apt)`; `TenementResidentPower.apartmentNumber` is public, with `Grid` and `MoveToGrid`. `ManufacturingPowerUI.GetUnitString` shows absolute values, with "+" for negative balances (production).
- New `TenementUpgradeCleanupArea` (SavableScript, a box trigger over tenement rooms): when a linked general or apartment upgrade changes level or progress it takes the furniture inside (`FurniturePlaceable.Take`, preplaced furniture only with `includePreplacedFurniture`) back to the inventory and packs loose items into a package (`packagePrefab` at `packagePoint`); it also compares a saved snapshot on load (`ShouldCleanup`), is gated by `cleanupTiers` (empty = all) and reports one summary per 0.5 s. Called from `TenementApartmentPrefabs` and `TenementGeneralPrefabs` (`UpdateUpgradeFurnitureAfterLoading` runs on `SaveController.LoadingDone`). Unchanged: `Generator`, `GeneratorPanel`, `PowerMeter`, `LightTurnOffOn`.

## Where power comes from: scene and prefab wiring `[data]` (read from build 0.5.13, re-read on 0.5.17)

- Grids: the interior scene of the tenement has 26 `TenementUtilities`, each with its own `PowerGrid` (BaseCapacity 0): one per apartment root (`Apartment 1` to `Apartment 17`, grids named "A1" to "A17"; #1 is the player's, #2 the shop) and the sub-areas `BuildingArea Player Apartment` and `BuildingArea Shop` (same apartment numbers), all with `useTenementPower` true; and seven general areas with apartmentNumber -1 (general, stairs, utility, basement, greenhouse, sauna, shrooms). The outdoor scene's tenement root has one more with -1; `TenementController` holds the main grid `Tenement_Power`. `TenementUtilities.AssignToPowerGrid` parents a grid to `powerMain` only when `HasElectricity()` (apartmentNumber below 0: always; otherwise `TenementApartment.currentElectricity != Off`) and to null otherwise, so every apartment and area grid is a direct child of `powerMain`. An apartment whose electricity upgrade is Off is therefore cut off in vanilla: its detached grid has capacity 0, every consumer under it is cut (`PowerInput` false, listeners fire `OnPowerOff`). The general areas stay connected and depend only on the building level (None means capacity 0).
- Finding a grid: placed furniture gets `FurnitureManager.powerGrid` from `TenementUtilities.Start` (every manager beneath it) and `BuildingSystem.ReconnectPower(obj, activeManager.powerGrid)`; a device or listener otherwise uses `GetComponentInParent<PowerGrid>()` first. With no grid found a `PowerSource` has `PowerInput = true`, so furniture outside every area is always powered.
- Lamps: 350 of 432 `LightTurnOffOn` in the tenement scene and upgrade prefabs are wired (338 of 420 in 0.5.13). The wiring is a `PowerGridListener` on the upgrade object (consumption by upgrade, e.g. walls 40 to 2200 W, kitchen 40 to 180 W, WC 40 to 120 W, stairwell 240 or 800 W, water 500 to 2000 W, heating 400 or 500 W, elevator 500 or 1200 W) whose `OnPowerOff` outputs call `LightTurnOffOn.TogglePower(false)` and `OnPowerOn` calls `TogglePower(true)` (338 pairs); other outputs call `SoundInfoAudioSource.Stop/Play`, `GameObject.SetActive`, `Storage.TogglePower` and `Elevator.TogglePower`. `TogglePower` sets `noPower`; meshes in the lamp's `lightMeshList` take `lightOffMaterial`, others stay lit. Unwired: the oven lamps inside stoves (`lamp_001_toggle` under `Crafting_oven`, device-managed), kitchen and heating devices, 13 environment lights, 3 facade lights. `LightController.electricLight` is read only by `LightCullZone` and `CameraShake`; it is not a power marker.
- Furniture with its own listener (switch default on unless noted; watts): Floor Lamp, Arc Floor Lamp, Bankers Lamp, Beer Lamp 50; Table Lamp, Ceiling Light, Plank Ceiling Light 60; Red Desk Lamp, Wall Light, Gradient Paper Ceiling Light 40; Orange Lava Lamp and the four Mushroom Lamp colours 30; Decoration Lights Small, Medium, Large 5; Work table 30; Bathroom Cabinet 20; fridges and freezers 100 to 133 (`Storage.TogglePower`); Big Television 200, Flat Screen Television 90, Old Television 180 and Table Fan 180 (switch default off); battery banks (`BatteryPowerSource.ToggleDrain`). No listener found for candles, lanterns, aquarium, terrarium, hydroponic and mushroom-cabinet lamps (device-managed through their own `PowerSource`) or Ceiling Lamp Chain (absence not double-checked).
- Televisions: Big, Flat Screen and Old Television have `TelevisionNoise.onOn`/`onOff` calling `PowerGridListener.Toggle(true/false)`, so the listener draws only while the TV is on, and its `OnPowerOff` calls `TelevisionNoise.PowerOff` (the saved `powerOn` flag, "No Power" state). Table Fan: the listener has the same `OnPowerOff` call but nothing toggles it on (empty outputs), so it never draws and is never cut. Old Computer has no listener. The TVs in the tenants' furniture upgrades (tv_001/002/003) have no listener and ignore the grid. `TelevisionNoise` itself never reads the grid.
- Main switch: three `Button` switches in the basement electricity-meter prefabs (Shit, Good, Best levels) call `PowerMeter.TogglePowerGrid(false/true)`, which with `useTenementMain` toggles `powerMain.GridEnabled` for the whole building; it is player-operated, nothing trips by itself.
- Overload: see "How it works": the parent grid cuts its own listeners (resident loads, whose `OnGridPowerOff` does nothing) most recently switched on first until `FreeCapacity >= 0`, then child grids cut their devices only if the parent is still negative; restoring is automatic and oldest first. There is no message or sound; light flicker comes from `unstableSupply` (true on `powerMain` unless the "TenementElectricity" subscription is active), not from overload. Hooks: no event; postfix `PowerGrid.UpdateGridStatus` or `PowerSource.OnGridPowerOff`, or subscribe your own `IPowerGridListener`.

## Changes in 0.5.19 `[code]`

- `PowerGrid.UpdateGridStatus` starts each pass by marking every listener that is on with `PowerBalance > 0` (a producer) as supplied again, so producers are never cut; only consumers are. The pass that sums producers now counts only `PowerSource`s with `RequiresFuel`.
- `PowerGridListener.HasSupply()` is new (true without a grid, with an unlimited grid, when on and `PowerGrid.IsPowered(this)`, or when off and `FreeCapacity >= PowerConsumption`); `OnGridPowerOff` and `OnGridPowerOn` set and clear `nocapacity`. `PowerMeter` shows the absolute maximum.
- `BatteryPowerSource.ManagePowerGrid` uses `IsPowered(powerListener)` instead of the sign of the consumption and returns the share of the load covered (0 to 1); when charging it returns 1 while a stack is active. In `OnSecondsPassed` a bidirectional bank drains `fuelDrainPerHour / 3600` as a whole (before it was divided by the number of stacks), and empty or full stacks only switch off when it is not bidirectional and drains in that direction.
